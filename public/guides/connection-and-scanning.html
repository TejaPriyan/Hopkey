Fix connection and scanning problems

A step-by-step way to isolate camera, network and device limitations.

By Teja Priyan · Updated 27 October 2026

When an online code will not connect

Check that both devices are using the current website and that the sender’s tab is still open. Enter the code carefully; unused online codes expire after ten minutes. Generate a new code if the first attempt is no longer active, and confirm any receiver approval or PIN requested by the sender.

If setup still fails, try a small transfer on a different permitted network. Some corporate, school, VPN or firewall configurations restrict WebRTC. Signaling can work even when the data connection cannot be established; a TURN relay may be needed on restrictive networks, and the deployment may not have one configured. HOPKEY cannot guarantee a direct path on every network.

When the scanner cannot use the camera

Open the HTTPS site and grant camera permission only when you want to scan. A local network HTTP address generally cannot request the same secure browser camera APIs. Check browser and operating-system camera permissions, close another application using the camera and select the correct device if more than one is present.

A screenshot or QR image upload can help with a static QR when camera access is unavailable. It does not replace scanning a complete animated transfer unless enough distinct frames are supplied. Never upload someone else’s private QR to a third-party decoder just to test it.

When animated QR scanning is slow

Keep the whole code inside the camera view with a clear margin. Reduce glare and hold both devices steady. Try a slower frame rate or the Reliable preset; the fastest preset only helps when the camera can resolve each frame. Keep the sender awake and avoid switching to a different tab during the sequence.

Test a short text transfer before a larger payload. If that succeeds, increase the size gradually. When reporting a bug, include both browser versions, transfer mode, approximate payload size and the exact error. Use a harmless sample instead of a real password, private document or active receive code.
